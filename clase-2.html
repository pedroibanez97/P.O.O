🧬 La herramienta

Se llama super()

class Persona:
    def __init__(self, nombre, edad):
        self.nombre = nombre
        self.edad = edad


class Jugador(Persona):
    def __init__(self, nombre, edad, nivel):
        super().__init__(nombre, edad)
        self.nivel = nivel

La diferencia, dibujada

print() ↓ PANTALLA

Lo veo… y se terminó ahí.

return ↓ RESULTADO
  • ✅ puedo guardarlo
  • ✅ puedo compararlo
  • ✅ puedo usarlo en otra cuenta
  • ✅ puedo devolverlo de nuevo

print() me muestra algo. return me entrega algo.

class Arma:

¿Por qué return y no print?

Paso 1 · la clase de arriba 
class Personaje:
    def __init__(self, nombre, vida):
        self.nombre = nombre
        self.vida = vida

    def esta_vivo(self):
        return self.vida > 0

    def recibir_daño(self, cantidad):
        self.vida = self.vida - cantidad

Todo lo que comparten todos los personajes: jugadores, enemigos, jefes.

¿Por qué esta_vivo() usa return y recibir_daño() no?

esta_vivo() contesta una pregunta → hay que devolver la respuesta.
recibir_daño() hace un cambio en el objeto → no tiene nada que entregar.

En pantalla
La clase base. Nada nuevo: es la clase 1 más un return.
Preguntá
La pregunta del cuadro. Es el mejor repaso posible del bloque 4.
Respuesta esperada
Uno responde, el otro modifica. Los métodos que solo cambian el objeto no necesitan devolver nada.
Revelá cuando
Alguien distinga “preguntar” de “hacer”. Es un criterio que les va a servir siempre.
Señalá
recibir_daño() modifica self.vida: el objeto se cambia a sí mismo, como acelerar() del auto de la clase pasada.
Paso 2 · el hijo, con arma 
class Jugador(Personaje):
    def __init__(self, nombre, vida, arma):
        super().__init__(nombre, vida)
        self.arma = arma

    def atacar_a(self, otro):
        daño = self.arma.atacar()
        otro.recibir_daño(daño)
        return daño

Línea 3: el padre pone nombre y vida.
Línea 4: el hijo agrega su arma.

En atacar_a(), ¿cuántos objetos participan?

Tres. El jugador le pide el daño a su arma, y se lo aplica al otro personaje.

En pantalla
La lámina donde se cruzan las cuatro herramientas. Recorré el método línea por línea, despacio.
Preguntá
“¿Quién sabe cuánto daño hace el ataque?” → El arma, no el jugador.
Respuesta esperada
Tres objetos: el jugador, su arma y el enemigo. Que los señalen en la pantalla.
Revelá cuando
Contaron los objetos. Es la idea más importante del día: los objetos se piden cosas entre ellos.
Señalá
otro es otro objeto que llega como parámetro. Un objeto puede recibir a otro objeto, igual que un número.
Error típico
Querer restar la vida directamente: otro.vida = otro.vida - daño. Funciona, pero rompe la encapsulación: para eso existe recibir_daño().
